## 本人が決めたこと（2026-11-12）
- 本番への出し方：テストとビルドが通れば、Claude の判断で main に push して本番に出してよい（あとで本人が確かめる）
- 端末：PC とスマホが半々。PC は表＋右に詳細、スマホはカード
- 一覧の1行：会社名、業界・地域・規模、上場かどうか、最新記事の日付・記事数、温度感・進捗
- 最初の並び順：最新記事が新しい順（あとで画面で切り替えられる）
- 並べ替え：表の見出しを押すとその列で並べ替え（もう一度で逆）。「次に」で同じ値のときの2番目の並べ替え（PC は Shift を押しながら見出し）。絞り込みと組み合わせられる
- 手で書く欄：メモ、次にやること・日付、担当（あとでパートナーに見せる範囲を決めるのに使う）
- 地域：地方＋都道府県
- 規模：資本金は必ず。従業員の目安は厚生年金の被保険者数（gBizINFO が日本年金機構のデータを半年ごとに取り込んだもの）。売上・BS は取れるなら取る
  - gBizINFO の財務は有価証券報告書（EDINET）を出す会社だけ。決算情報（官報）は公開を許諾した法人だけ
  - 非上場の売上・BS は有料のデータも検討する（比べた結果を本人に報告済み。まだ何も買わない）
  - 無料：gBizINFO の決算情報（官報掲載のうち公開を許諾した法人）は一括ファイル（決算情報 zip）でだけ取れる。ダウンロードに API トークンが要るので、段階2で Long List の Cloud Functions（Secret Manager の GBIZINFO_TOKEN）から件数を数える
  - 有料の候補：Compalyze（決算公告の数字を法人番号付きで CSV・API）、TSR・TDB の1社ずつの購入（実際の売上）。官報情報検索サービスと官報発行サイトは規約で機械的な収集が禁止なので使わない
  - Compalyze のサイトは人の確認画面があり自動では読めない。規約（社内の一覧に取り込んでよいか）は本人が問い合わせで確かめる
  - **会社 HP は台帳側が読む（2026-11-12 本人の指示）**：`companyWebSweep`（prtimes-inbox の functions/src/web.ts、5分ごとに6社ずつ＝1日約1,700社）が robots.txt を守って読み、正式な会社名・所在地・従業員数・資本金・売上高を出どころ付きで `companies.web` に、ページの本文を `companyWeb` に書く。Long List は自分で読みに行かず、依頼は `webQueue/{会社ID}` に書く（会社の詳細の「HP を読んでもらう」ボタン）。一覧は、ほかに情報がないときだけ `companies.web` の資本金・従業員数・売上高・正式な名前を使う
  - **自前で集める（2026-11-12 本人が決定）**：段階4の AI のお試し（200社）で、会社 HP（`companyWeb` の本文）と PR TIMES の記事も AI に読ませ、売上・決算公告の数字を拾う。数字には出どころ（ページの URL）と年度を付ける。HP は robots.txt を守り、ゆっくり読む。何割取れるかを見て、全社に広げるか・有料を使うかを決める
  - 保存先は台帳（prtimes-inbox の `companies`）。業界タグと同じく台帳側の処理として足す（Knowledge Base でも使う）
  - 官報（発行サイト・検索サービス）は規約で機械的な収集が禁止なので読まない。登記は有料なので使わない
- 除外：自治体・大学・海外企業に加えて、一般・公益の社団/財団法人、NPO 法人、学校法人。医療法人・社会福祉法人は残す
- 除外した会社は別の画面で確認でき、間違いなら戻せる
- 除外の追加（2026-11-12）：PR TIMES の「〇〇PR事務局」「〇〇実行委員会」「〇〇プロジェクト」など催し・宣伝のための名前（会社ではない）。「（一社）」「（公財）」「（特非）」など略した書き方も読む
- 法人格：法人番号が決まった会社は正式な名前（gBizINFO の法人名＝国税庁の法人番号の登録）を画面・CSV に出し、法人格もそこから読む。決まっていない会社は PR TIMES の名前から読み、書いていなければ「不明」。法人格の書いていない名前（個人の事業や、法人格を省いた書き方）は、国税庁の法人番号 API が使えるようになったら見直す

## 業界タグ（2026-11-12 本人が決定）
- メイン1つ＋サブ2つまで（サブはなくてもよい）、BtoB／BtoC／両方も付ける。材料は PR TIMES の記事の見出し（新しい順に30件）・PR TIMES の業種・gBizINFO の事業の概要・HP の会社名
- 処理は台帳側の `industryTagsSweep`。Long List は `industryQueue/{会社ID}` に頼み（models に AI の名前、全社に付けるときは apply に決めた AI）、答えは `industryTrials`（AI ごと）と `companies.industryTags`（決めた AI）を読む。分類の名前は `meta/industryTags`
- お試し：画面の「タグのお試し」（または GitHub Actions の tag-trial：start / status。ログは件数だけ）で200社をくじ引き → まず Sonnet、同じ200社で Haiku・Opus。本人が ○△× を付け（`longlistTrials/t1`）、○の割合と費用で AI を決めてから全社に付ける

## データの流れ（段階2）
- Cloud Functions `longlistBuildIndex`（codebase longlist、6時間ごと＋デプロイの直後）が台帳の `companies`・`companyArticles` を読み、一覧用のまとめ `longlistIndex/{番号}`（1行1社の配列を JSON にして gzip した Bytes。1つ 900KB まで）と目次 `longlistMeta/index` を書く
- 画面はまとめを読み、絞り込み・並べ替えは端末の中で行う。本人が付けるものは `longlist/{会社ID}`（画面が書く）
- 会社を開いたときだけ、`companies`・`companyArticles`・`handoff`（その会社の記事IDで探す）を読む。CSV は代表者・電話・HP を `companies` から30社ずつ読む
- 除外は名前と所在地で自動判定（`src/lib/exclude.ts`）。間違いは画面で戻せる（`longlist/{会社ID}.exclude`）
- 手元で試すとき：Firestore・Auth のエミュレータを起動して `VITE_EMULATOR=1 npm run dev`、`__devLogin(メール, パスワード)` でログイン
